# Observability and load testing

## Stack (`--profile obs`)

| Service | Port | Notes |
|---|---|---|
| Prometheus 3.16 | 7909 | 10 s scrape, 2-day retention; config `infra/prometheus/prometheus.yml` |
| Grafana 13.2 | 7300 | anonymous Viewer; admin password `GRAFANA_ADMIN_PASSWORD` (default `arth`); dashboard "Arth overview" provisioned |
| Jaeger 2.23 | 7686 (UI), 4317/4318 (OTLP) | in-memory store |

```sh
OTEL_ENDPOINT=http://jaeger:4318 OTEL_EXPORT=true \
  docker compose -f infra/docker-compose.yml --profile core --profile realtime --profile ai --profile obs up -d
```

Without `OTEL_ENDPOINT`, the Node and ai services create no exporter, and the api keeps `OTEL_EXPORT=false`. Spans are still created, but they are never sent anywhere.

## Dashboard

`infra/grafana/dashboards/arth.json` is generated by `python3 infra/grafana/gen_dashboard.py`. Edit the generator, not the JSON. It has 31 panels in 7 rows:
- overview;
- stream gateway (sockets, frames/s, bytes/s, backpressure closes);
- ingest (tick age, flush time, consumer lag);
- alerts and notifications (fired, sent, retried, DLQ);
- api (RPS, p95/p99 by URI, 5xx);
- AI copilot (turns, latency, tokens by `dir`, tool time, guard rewrites);
- runtime (heap, event-loop lag, GC).

## Errors (Sentry)

The DSN comes from `SENTRY_DSN`, or `EXPO_PUBLIC_SENTRY_DSN` in the app. When the DSN is unset, Sentry is a no-op. Every SDK runs a `beforeSend` scrubber before an event leaves:
- it drops user, request and extra fields, and frame variables;
- it masks email, PAN, Aadhaar, +91 phone numbers and JWTs in messages and exceptions;
- in the app, it also drops `fetch`/`xhr` breadcrumbs.

The app starts Sentry only while the user is signed in **and** has granted the `analytics` consent, and stops it when that consent is withdrawn. `tracesSampleRate` is 0 everywhere. Tracing goes through OTel instead.

## Load tests (k6)

| Script | What it does | Thresholds |
|---|---|---|
| `infra/load/rest.js` | Weighted mix of instruments, candles, watchlists and portfolio requests through nginx | <1% errors; p95 candles 300 ms, instruments 200 ms, portfolio 400 ms, watchlists 200 ms |
| `infra/load/ws.js` | N sockets on the gateway (default 1,000, 3 min), each with a 20-symbol window; tokens minted locally with the dev `JWT_SECRET` | p95 first frame < 1 s, p99 frame gap < 1.5 s, fewer than 10 abnormal closes |

```sh
k6 run infra/load/rest.js
k6 run -e SOCKETS=5000 -e HOLD=600 infra/load/ws.js
```

Record results in `docs/perf/BACKEND.md` with the hardware they ran on.

## Mobile E2E (Maestro)

The flows are in `apps/mobile/.maestro/`: `login`, `add-to-watchlist`, `open-chart` and `ask-copilot`, which share the `subflows/sign-in` subflow. They need a dev build on an emulator and the stack on `core` + `realtime` (+ `ai` for the copilot flow):

```sh
cd apps/mobile && maestro test .maestro
```
